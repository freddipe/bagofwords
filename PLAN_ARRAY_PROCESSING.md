# Plan Array Processing in Agent Execution

**Location**: `backend/app/ai/agent.py:158-730`

This document explains how the Planner-generated plan array is processed by the Agent to execute actions and create widgets.

---

## Overview

The Agent uses a **ReAct Loop** (Reason → Act → Observe) to process user requests:

```
1. PLAN:    Planner generates a plan with actions
2. EXECUTE: Agent processes each action sequentially
3. OBSERVE: Agent collects results and passes to next iteration
4. REPEAT:  Loop continues until analysis_complete = true
```

---

## Plan Structure from Planner

**Generated by**: `backend/app/ai/agents/planner.py`
**Received at**: `backend/app/ai/agent.py:183`

### JSON Structure

```json
{
  "analysis_complete": false,
  "reasoning": "The user wants to see revenue by region...",
  "plan": [
    {
      "action": "create_widget",
      "prefix": "Let me create a bar chart showing revenue by region...",
      "execution_mode": "sequential",
      "action_end": true,
      "requires_observation": true,
      "details": {
        "title": "Revenue by Region",
        "data_model": {
          "type": "bar_chart",
          "columns": [...],
          "series": [...]
        }
      }
    }
  ],
  "streaming_complete": true,
  "text": "I'll create a visualization...",
  "token_usage": {"input_tokens": 1500, "output_tokens": 800}
}
```

### Plan Fields Explained

| Field | Type | Description |
|-------|------|-------------|
| `analysis_complete` | boolean | If `true`, stops the ReAct loop |
| `reasoning` | string | Internal reasoning shown to user |
| `plan` | array | List of actions to execute |
| `streaming_complete` | boolean | Indicates Planner finished streaming |
| `text` | string | Human-readable explanation |
| `token_usage` | object | LLM token consumption stats |

## Action Structure

Each action in the `plan` array has:

```json
{
  "action": "create_widget",           // Action type
  "prefix": "Creating chart...",       // User-visible message
  "execution_mode": "sequential",      // Execution strategy
  "action_end": true,                  // True when action is complete
  "requires_observation": true,        // If true, pause for observation
  "details": {                         // Action-specific details
    "title": "Widget Title",
    "data_model": {...}
  }
}
```

### Action Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `action` | string | ✅ | Action type: `create_widget`, `modify_widget`, `answer_question`, `design_dashboard` |
| `prefix` | string | ❌ | User-visible message shown in chat |
| `execution_mode` | string | ❌ | `"sequential"` or `"parallel"` (currently only sequential is used) |
| `action_end` | boolean | ❌ | If `true`, action is complete and should be executed |
| `requires_observation` | boolean | ❌ | If `true`, pause after this action for observation |
| `details` | object | ✅ | Action-specific parameters |

## Action Results Tracking

**Location**: `backend/app/ai/agent.py:133, 164`

The Agent tracks state for each action using `action_results`:

```python
action_results = {
    "action_0": {
        "prefix_completion": Completion object,  # Chat message for this action
        "widget": Widget object,                 # Created widget
        "step": Step object,                     # Created step
        "completed": False,                      # Execution status
        "status_set_to_success": False,          # Tracks if completion marked success
        "answer": "Full answer text..."          # For answer_question actions
    },
    "action_1": {...},
    "action_2": {...}
}
```

### Why Track Action Results?

1. **Prevent Duplicate Work**: Skip actions already completed
2. **Maintain State**: Associate widgets/steps with actions
3. **Update UI Progressively**: Create/update completions as actions stream
4. **Build Observations**: Collect results for next ReAct iteration

## The ReAct Loop

**Location**: `backend/app/ai/agent.py:158-730`

```python
analysis_step = 0
analysis_complete = False
observation_data = None

# Loop until complete or max steps reached
while (not analysis_complete) and (analysis_step < max_steps):
    # Reset action results for each step
    action_results = {}

    # 1. PLAN: Get actions from planner
    plan_generator = self.planner.execute(
        schemas,
        persona,
        prompt,
        memories,
        previous_messages,
        observation_data,  # ← Results from previous iteration
        widget,
        step,
        external_platform,
        sigkill_event
    )

    # 2. EXECUTE: Process each action
    async for json_result in plan_generator:
        for i, action in enumerate(json_result['plan']):
            # ... handle action (see below)

    # 3. OBSERVE: Collect results
    observation_data = {
        "widgets": []
    }
    for action_id, result in action_results.items():
        if result["completed"] and result.get("widget") and result.get("step"):
            widget_data = await self._build_observation_data(
                result["widget"],
                result["step"]
            )
            observation_data["widgets"].append(widget_data)

    # 4. CHECK: Should we continue?
    if json_result.get("analysis_complete") == True:
        analysis_complete = True
        break

    analysis_step += 1
```

if action_type == 'design_dashboard':
    # 1. Get widgets and steps
    widgets_steps = await self._get_report_widgets_and_steps(self.report.id)
    widgets = [ws[0] for ws in widgets_steps if ws[0] is not None]

                partial_design['prefix']

                    await self.project_manager.update_widget_position_and_size(
                        self.db,

                            block['x'], block['y'],
                            block['width'], block['height'],

## Requires Observation

**Location**: `backend/app/ai/agent.py:702-705`

```python
# Check if this action requires observation
requires_observation = action.get('requires_observation', False)
if requires_observation and action_results[action_id]["completed"]:
    # Stop processing more actions if observation is required
    break
```

### Purpose

Forces the agent to:
1. **Stop** processing remaining actions in current plan
2. **Build observation data** from completed actions
3. **Pass to Planner** for next iteration
4. **Get new plan** based on results

### Example Use Case

```json
{
  "plan": [
    {
      "action": "create_widget",
      "details": {"title": "Sales Data"},
      "requires_observation": true  // ← Pause after this
    },
    {
      "action": "create_widget",
      "details": {"title": "Another Chart"}  // ← Won't execute yet
    }
  ]
}
```

The second action won't execute until the next ReAct iteration, allowing the Planner to see the results of the first widget before deciding how to proceed.

## Key Takeaways

1. **ReAct Loop**: Agent repeats Plan → Execute → Observe until complete
2. **Action Results Tracking**: Maintains state across streaming and iterations
3. **Prefix Completions**: User sees progress via chat messages
4. **Widget/Step Creation**: Entities created incrementally as plan streams
5. **Observation Data**: Results from one iteration inform the next plan
6. **Four Action Types**: `create_widget`, `modify_widget`, `answer_question`, `design_dashboard`
7. **Sequential Execution**: Actions run one at a time
8. **Requires Observation**: Forces pause between dependent actions
9. **Error Resilience**: Failed actions don't crash the loop
10. **Sigkill Support**: Users can stop execution at any time

The plan array is the **blueprint** that transforms user intent into executable actions, with the Agent as the **orchestrator** that brings the plan to life!
